# GUILD∞ Pocket — おバカ開拓村

User brief: preserve the simple, slightly ridiculous gathering/building loop and substantially improve smartphone quality. Direction selection and implementation are delegated by the user.

Three alternatives: village-first (selected), wave-defense-first, mobile wandering settlement. Preserve village-first identity; borrow periodic meaningful choices from defense games.

Baseline: exact PR127 head 4f78c04d. Keep analog drag, automatic gathering, original procedural audio, four gates, no wall archers, 16 tower cap, no camera shake, repeat construction and automatic saving. Do not touch unrelated Work games.

New version has a separate entry point and save namespace. Retain legacy engine and tested routing. Add focused presentation/system modules: responsive Japanese HUD, readable bottom sheets, dynamic drag indicator, keyboard support, pause while menus/hidden, improved pixel environment and actors, short localized feedback, gathering chains, a cooldown whistle, night-earned village policies, finite milestones and exploration caches. Choices persist; rewards cannot be collected twice; reset remains two-stage. No monetization or external runtime assets.

Targets: 360x640, 390x844, landscape 844x390; primary touch targets at least 44 CSS px; no horizontal overflow. Verify real browser pointer input, building/hiring, save reload, choice uniqueness, cache uniqueness, pause/input cleanup, gate traversal and absent wall arrows. Real iPhone performance remains a separate validation need.

Research: https://kingdomthegame.com/kingdom-two-crowns/ (minimalist build/recruit/defend reference); https://selfdeterminationtheory.org/wp-content/uploads/2014/04/2009_PrzbylskiRyanRigby_PSPB.pdf (competence/autonomy and enjoyment). Design hypotheses, not claims of guaranteed retention.
