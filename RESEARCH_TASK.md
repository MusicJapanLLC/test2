# GUILD∞ RESEARCH TASK — 300+ REVIEW ANALYSIS

Owner requirement: before major retention/game-loop expansion, perform a real research pass and convert it into implementation hypotheses

## Mission

Analyze **300+ real user reviews / comments / discussions** across relevant games and UX references

The goal is not to collect praise/complaints mechanically
The goal is to answer:

- Why do people keep playing?
- Why do they quit?
- What feels good repeatedly?
- What becomes annoying after hours?
- What makes them reopen the game tomorrow?
- Which feedback can be turned into a concrete GUILD∞ mechanic?

## Reference groups

1. Romancing SaGa series
2. Bravely Default series
3. Splatoon series
4. Clash Royale
5. Super Smash Bros. series
6. Guild-management / idle / town-management games
7. Mobile RPG / management games
8. Short-form content UX / behavioral design research

## Required coding dimensions

For every collected sample, tag when applicable:

- title / product
- source
- positive / negative / mixed
- retention reason
- churn reason
- control feel
- UI
- pacing
- progression
- reward
- audio
- mobile usability
- comeback / return motivation
- frustration
- suggested GUILD∞ implication

## Minimum output

- >= 300 samples
- source counts
- title counts
- top recurring positive patterns
- top recurring negative patterns
- contradictions between audiences
- 10-20 implementation hypotheses
- impact / effort estimate
- top 5 experiments for the current prototype

## Psychology / UX layer

Evaluate patterns using concepts such as:

- flow
- mastery
- competence
- curiosity
- immediate feedback
- goal gradient
- progress visibility
- variable content
- session rhythm
- habit loop
- collection / discovery
- return reward

Do not propose coercive paywall pressure, fake urgency, deceptive notification loops, or gambling-like monetization as the core retention mechanism

The desired result is **high intrinsic retention**: the player keeps playing because the controls, feedback, progression, discovery, music, and world feel good

## Implementation gate

Research is not complete until findings are translated into specific GUILD∞ experiments

Each experiment must state:

- hypothesis
- exact mechanic
- expected player feeling
- metric / observable behavior
- implementation cost
- failure mode
- rollback plan
